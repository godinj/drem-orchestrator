## Seth Root-Cause Recommendation

Seth recommends one P0 orchestrator bugfix task for the parent/subtask lifecycle, not a Grafana product task. Kyle accepts that classification.

Required fix semantics:

- Parent reconciliation must compute an explicit active test-subtask set before deciding parent state.
- Superseded/replaced children must be excluded from failure accounting once their active replacement exists.
- Replacement lineage must be durable and queryable through `replacement_of` / `supersedes` fields or a parent-scoped generation number, not inferred from title suffixes.
- Parent `test_writing` should advance to `test_review` when all active test subtasks are `done`.
- Parent `test_writing` should fail only when an active child is terminal-failed or rejected without an active replacement.
- Legitimate parent failure reasons must include active failed/rejected child IDs and titles; reconciliation must not emit `test subtasks failed: ` with a blank suffix.
- `dremctl retry` / orchestrator retry must move the parent to backlog and synchronously notify the supported scheduler task-ready wake path so re-entry does not depend only on a later sweep.

Required regression coverage:

- Superseded rejected original `e920516b` plus done replacement `b42b8d4e` transitions parent `28b8876b` from `test_writing` to `test_review`, not `failed`.
- Active replacement rejected/failed transitions parent to `failed`, with the active replacement ID/title in the reason.
- Superseded rejected test child plus done replacement plus unrelated backlog implementation children does not count future implementation backlog as failed tests.
- Retry from failed on a parent with backlog children records `failed -> backlog`, emits the scheduler wake/task-ready signal, and advances within a bounded fake-clock/tick window.
- Retry idempotency does not duplicate children, resurrect superseded children as active, or strand assigned-worker fields.
