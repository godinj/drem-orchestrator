# Agent: C-Suite Images and Per-Project Compose Template

You are working on the `master` branch of Drem Orchestrator, a Go-based multi-agent task orchestrator. Your task is Phase 3 integration work for the containerization initiative: build the C-Suite container images (Mike, Alex, Ross, Seth), build the orchestrator image in both production and development modes, and fill in the per-project compose template that prompt 05 skeletoned. When this prompt lands, `drem project register` produces a working compose file that brings up an entire per-project stack.

## Deliverables

### C-Suite images

#### 1. `deploy/docker/csuite-base.Dockerfile`

Shared base for all four C-Suite agents.

- `FROM debian:bookworm-slim`
- Install `git`, `ca-certificates`, `curl`, `jq`, `nodejs`, `npm`, `tini`
- Install `@anthropic-ai/claude-code` globally (same pinned version as worker images — prompt 10)
- Create user `drem` (UID 1000), `/home/drem`
- Copy the C-Suite prompt directory (e.g. `/agents/csuite/` or whatever the repo lays out) into `/opt/csuite/prompts/`
- `ENTRYPOINT ["/usr/bin/tini", "--"]`
- `USER drem`

Tag: `localhost:5000/drem-csuite-base:latest`.

#### 2. `deploy/docker/csuite-mike.Dockerfile` (and alex, ross, seth — four files)

Each is a thin layer over `csuite-base`:

- `FROM localhost:5000/drem-csuite-base:latest`
- `ENV CSUITE_AGENT=mike` (or `alex`, `ross`, `seth`)
- `CMD ["/usr/local/bin/csuite-run.sh"]`

One `csuite-run.sh` (baked into `csuite-base`) reads `CSUITE_AGENT` and execs the appropriate Claude session against `/opt/csuite/prompts/${CSUITE_AGENT}.md`. These containers are warm — the entrypoint is a persistent loop that listens on the csuite-watcher socket or polls the orchestrator for prompts to run.

Tags: `localhost:5000/drem-csuite-{mike,alex,ross,seth}:latest`.

#### 3. `deploy/docker/csuite-watcher.Dockerfile`

Multi-stage Go build of the existing `csuite-watcher/` binary. Runtime: distroless. Tag: `localhost:5000/drem-csuite-watcher:latest`.

### Orchestrator image

#### 4. `deploy/docker/orch.Dockerfile` (production)

Multi-stage Go build:

- Build stage: `golang:1.24.4` builds `./cmd/drem`
- Runtime stage: `gcr.io/distroless/static-debian12` with just the binary
- `ENTRYPOINT ["/usr/local/bin/drem", "orchestrator"]` (or whatever the orchestrator subcommand is)

Tag: `localhost:5000/drem-orch:latest`.

#### 5. `deploy/docker/orch-dev.Dockerfile` (development)

- `FROM golang:1.24.4-bookworm`
- Install `git`, `ca-certificates`
- `WORKDIR /src`
- `CMD ["sh", "-c", "go build -o /bin/drem ./cmd/drem && exec /bin/drem orchestrator"]`
- At compose time, the project's source directory is bind-mounted at `/src`. Developer restarts the container to pick up changes.

Tag: `localhost:5000/drem-orch-dev:latest`.

Kyle always runs the baked image (prompt 14 already specifies this); only the orchestrator has a dev variant.

### Per-project compose template

#### 6. `internal/projects/templates/project-compose.yml.tmpl`

Replace the TODO skeleton from prompt 05 with the full service set. Template variables in `{{...}}` are filled by `projects.Render`:

```yaml
# Generated by `drem project register` — do not edit by hand.
# Regenerate with `drem project register --update {{.ProjectName}}`.

version: "3.9"

networks:
  drem-net:
    external: true

volumes:
  drem-{{.ProjectName}}-db:
  drem-{{.ProjectName}}-prompts:

services:
  orch:
    image: {{.OrchImage}}
    environment:
      DREM_PROJECT: "{{.ProjectName}}"
      DREM_BARE_REPO: "{{.BareRepoPath}}"
      DREM_DB_PATH: "/var/lib/drem/drem.db"
      DREM_ORCH_LISTEN: ":8080"
      DREM_SPAWNER_SOCKET: "/var/run/drem/spawner.sock"
      DREM_AGENTMON_TOKEN: "{{.SharedToken}}"
    volumes:
      - drem-{{.ProjectName}}-db:/var/lib/drem
      - drem-{{.ProjectName}}-prompts:/var/lib/drem/prompts
      - {{.BareRepoPath}}:/bare:rw
      - drem-spawner-sock:/var/run/drem:ro
    networks: [drem-net]
    labels:
      drem.project: "{{.ProjectName}}"
      drem.service: orch
    ports:
      - "127.0.0.1:{{.OrchHostPort}}:8080"
    restart: unless-stopped

  agentmon:
    image: localhost:5000/drem-agentmon:latest
    environment:
      DREM_PROJECT: "{{.ProjectName}}"
      DREM_ORCH_URL: "http://orch:8080"
      DREM_AGENTMON_TOKEN: "{{.SharedToken}}"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
    networks: [drem-net]
    labels:
      drem.project: "{{.ProjectName}}"
      drem.service: agentmon
    depends_on: [orch]
    restart: unless-stopped

  csuite-watcher:
    image: localhost:5000/drem-csuite-watcher:latest
    environment:
      DREM_PROJECT: "{{.ProjectName}}"
      DREM_ORCH_URL: "http://orch:8080"
    networks: [drem-net]
    labels:
      drem.project: "{{.ProjectName}}"
      drem.service: csuite-watcher
    depends_on: [orch]
    restart: unless-stopped

  csuite-mike:
    image: {{index .CsuiteImages "mike"}}
    environment:
      DREM_PROJECT: "{{.ProjectName}}"
      DREM_ORCH_URL: "http://orch:8080"
    networks: [drem-net]
    labels:
      drem.project: "{{.ProjectName}}"
      drem.agent_type: csuite-mike
    restart: unless-stopped

  csuite-alex:
    image: {{index .CsuiteImages "alex"}}
    # ... same shape as mike
  csuite-ross:
    image: {{index .CsuiteImages "ross"}}
    # ... same shape as mike
  csuite-seth:
    image: {{index .CsuiteImages "seth"}}
    # ... same shape as mike

  merger-pool:
    image: {{.MergerImage}}
    environment:
      DREM_PROJECT: "{{.ProjectName}}"
      DREM_ORCH_URL: "http://orch:8080"
      DREM_AGENTMON_TOKEN: "{{.SharedToken}}"
    volumes:
      - {{.BareRepoPath}}:/bare:rw
    networks: [drem-net]
    labels:
      drem.project: "{{.ProjectName}}"
      drem.agent_type: merger
```

#### 10. `deploy/docker/build-csuite.sh`

Build-and-push script mirroring prompt 10's `build-workers.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail
cd deploy/docker

docker build -t localhost:5000/drem-csuite-base:latest    -f csuite-base.Dockerfile    context/
for agent in mike alex ross seth; do
  docker build -t "localhost:5000/drem-csuite-${agent}:latest" -f "csuite-${agent}.Dockerfile" context/
done
docker build -t localhost:5000/drem-csuite-watcher:latest -f csuite-watcher.Dockerfile context/
docker build -t localhost:5000/drem-orch:latest           -f orch.Dockerfile           ../../
docker build -t localhost:5000/drem-orch-dev:latest       -f orch-dev.Dockerfile       ../../

for img in drem-csuite-{base,mike,alex,ross,seth,watcher} drem-orch drem-orch-dev; do
  docker push "localhost:5000/${img}:latest"
done
```

## Scope Limitation

- No per-project customization of the C-Suite agents beyond swapping images via `ContainerImageOverrides`. The agent prompts baked into `drem-csuite-base` are shared across projects.
- No multi-instance per-project C-Suite. Each project gets exactly one Mike, one Alex, one Ross, one Seth.
- No GPU pinning for C-Suite containers. They call SGLang through the network; they do not themselves need GPU access.
- No dynamic merger pool scaling. The `replicas: 2` value is static for the first cut.
- Do not modify `internal/csuite/` Go code in this prompt. Wiring happens through env vars; the package should not need changes. If it does, flag it to the user rather than guessing.
